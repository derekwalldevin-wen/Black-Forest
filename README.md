## 一、怎么跑

项目是 **Phaser 3.80.1 + 原生 JavaScript，零构建步骤**。但 Phaser 用 XHR 加载图片，
`file://` 直接双击打开会被浏览器拦截，所以需要一个本地服务器。

```powershell
python -m http.server 8899 --bind 127.0.0.1
```

然后浏览器打开 `http://127.0.0.1:8899/index.html`。

> **手机真机试玩**：确保手机和电脑在同一 WiFi，用电脑局域网 IP 访问
> `http://<你的内网IP>:8899/index.html`。竖屏锁定由 `viewport-fit=cover` +
> `Phaser.Scale.FIT` + `CENTER_BOTH` 负责，自动等比缩放并留黑边。

> ⚠️ **改代码后浏览器会缓存旧 JS**。验证改动时换一个端口起服务器，否则你看到的还是旧版本。

## 二、这一版做了什么

这一版是一次结构级重构，不是加内容。核心是把游戏从「哥特暗黑童话」扩成**双世界**：

### 1. 双世界结构

森林之主死后，你踩碎树根，脚下不是土，是青铜的台阶。从这里开始翻进《山海经》。

| 章 | 境域 | 名称 | 三场敌人 |
|---|---|---|---|
| 一 | gothic | 迷雾林缘 | 灰狼 → 毒蝇伞 → 头狼 |
| 二 | gothic | 腐沼深处 | 森林女巫 → 铁鬃野猪 → 沼泽女巫 |
| 三 | gothic | 永夜王座 | 灰狼 → 头狼 → **黑暗森林之主** |
| — | — | *（踩碎树根，露出青铜阶）* | — |
| 四 | shanhai | 青丘之国 | 九尾狐 → 鹿蜀 → **穷奇** |
| 五 | shanhai | 毒泽九首 | 相柳 → 蜚 → **祸斗** |
| 六 | shanhai | 帝鸿之末 | 饕餮 → 白泽 → **帝江**（BOSS，120-128 HP） |

**6 章 × 3 场 = 18 战**。粗体是精英 / BOSS。打完每章最后一场不进事件，先给奖励。

**没有一行代码因为换皮而改过**：

> v3 更新：**卡面曾经是唯一的例外**——`CardView._build()` 里手搓 `fillRoundedRect`，
> 东方篇的牌还是哥特圆角。现在卡面也收敛到 `theme.js` 的绘制函数里，
> 这个例外没有了。详见第三节。

**实现方式**：`PAL` / `FONT` / `TYPE_STYLE` 是全局共享的**可变对象**，
`applyTheme(key)` 原地改写它们。所有场景里已经写好的 `PAL.gold` 会自动跟着变。
真正需要按主题分叉的只有「怎么画」，收敛到三个函数：

```js
drawPanel(g, x, y, w, h, opts)   // 圆角 / 方角回纹
drawMotif(scene, cx, cy, size)   // 月晕 / 回纹方胜
drawDivider(g, x1, x2, y, color) // 细金线 / 双线菱结
```

跨过第三章 → 第四章时会播一次青铜幕布转场（`playRealmTransition`）。

### 3. 灵韵：第二资源条 + 共鸣

**灵韵**是独立于行动力的第二条资源。每个回合自然 +1，**用不掉会攒着**，所以符箓可以跨回合铺。

**共鸣**是灵韵这条线真正想制造的决策：

> 本回合每打出一张符箓，共鸣 +1；之后打出的符箓费用按共鸣数递减，最低 0。

一张 3 费的「太一击」，连打三张实际花费 3+2+1 = **6**；隔回合零敲碎打是 3+3+3 = **9**。
省下的 3 点灵韵，就是「把手里的符箓串成一条链」的回报。

共鸣会实时反映到卡面上：右上角的小金点亮起，费用数字直接变小。

### 8. `src/core/combat.js` —— 战斗算式抽成纯逻辑层

v2 的第二个架构决定。`hitEnemy` / `intakeDamage` / `gainBlock` / `tickStatuses`
从 `CombatScene`（1179 行）里抽到 86 行的纯算式模块，场景通过 `hitEnemyCore` 等别名调用。

**为什么**：第 9 节的模拟器要读同一批数据文件跑 3000 局。如果算式留在场景里，
模拟器就得抄一份，抄的那份迟早和真实游戏跑偏——**测出来的曲线是假的**。
抽出来之后，模拟器和实际游戏跑的是同一份代码。

### 9. 数值平衡：不是拍脑袋，是 3000 局跑出来的

v2 的第三件事，也是花时间最多的。先建工具（`tools/simulate.js`，397 行），
让一个贪心 AI 用真实的卡池 / 敌人脚本 / 事件 / 遗物连打 3000 局，
然后**用数据改数据**。

```powershell
node tools\simulate.js 3000                        # 当前难度曲线
node tools\simulate.js 3000 --chapters=3           # 对照组：只跑前三章
node tools\simulate.js 1500 "--hp=forest_lord:76,84"  # 沙箱内调参，不改源码
```

#### 关键发现 1：不是「某场太难」，是**复利消耗**

对照组实验最能说明问题：

| 版本 | 贪心 AI 全程通关率 |
|---|---|
| 3 章 9 战 | **10.1%** |
| 6 章 18 战（直接照搬原难度） | **0.1%** |

同样的 9 场战斗，难度没变，通关率掉了 100 倍。
**问题是每场战斗之间的资源复利衰减**——血量回不满、牌组不成长、
到第 12 场时的期望战力撑不住第 12 场的敌人。

#### 由此引入的机制：战后恢复

`RUN.healAfterFight(isBig)` —— 普通战回 **26%** 生命上限，
精英 / BOSS 战回 **42%**。这是对冲复利最直接的手段，
让一次失败不至于把后面 9 场一起拖死。

#### 关键发现 2：BOSS 不是「伤害太高」，是 `once` 机制缺失

调森林之主时发现一个真 bug：`rollIntent` **每回合独立重抽、无记忆**。
于是自我强化的 pattern 会被反复抽中，而 `strength` 不在 `DECAY_STATUSES` 里
（本该永久），导致 BOSS 的力量**线性叠到 +8**，终阶段一刀打 48 点。

修法不是手改 16 处数值，而是：`ENEMY_DEFS` 加载后自动遍历，
给**每个含 `buff` 的 pattern 打上 `once = true`**（`lu_shu` 除外——那是刻意的交替设计）。
`rollIntent` 优先从未用过的 once pattern 里抽，全用完则回退整个池，
保证任何血量比例都抽得到意图。

> 以后新增敌人只要写了 `buff`，就自动受这条约束，不用记得手动维护。

修正前后：**森林之主通过率 1.7% → 2.8%**（同一基准 AI）。

#### 关键发现 3：两个 BOSS 的血量是错的

参数扫描显示，森林之主 120 血时它把后 9 战的到达率压到 **1%**：
玩家到第 9 战实际 DPS 约 18/回合，打完要 7 回合；
而它每回合打 16~20 点，70 血只够活 4 回合——**数学上就过不去**，不是难。

| 敌人 | 原 HP | 改为 |
|---|---|---|
| `forest_lord` | 120 | **76~84** |
| `dijiang` | 172 | **120~128** |

同时压低两个 BOSS 终阶段的伤害尖峰（`atk11×3=33` → `atk8×3=24`；
`atk12×3=36` → `atk9×3=27`）。

## 三、卡面与界面（v3）

### 1. 先说清楚 v2 之前的卡面为什么"不精美"

不是配色没调好，是**结构错了**。旧卡面是 `CardView._build()` 里手搓的一段
`fillRoundedRect` + 一个 `Text` + 一个矢量小图形，直接铺在屏幕上：

| 问题 | 后果 |
|---|---|
| **完全没走主题层** | 东方篇的牌还是哥特圆角，跟旁边方角回纹的按钮/面板割裂——「四个界面自动换皮」其实漏了卡面 |
| 没有画窗 / 铭牌 / 描述框 | 牌面就是一块深色矩形 + 几行小字，没有信息分层 |
| 类型色是 22% 透明度糊在顶端一条 | 看起来像没擦干净的水渍，不像设计过的绶带 |
| 费用是一个扁平圆点，稀有度是底部一个点 | 两个最该被一眼看到的信号反而最弱 |
| 手牌按「创建那一刻的手牌数」取尺寸 | 第一张牌拿到 300×450、第五张只有 200×300，扇形越往右牌越小、叠成一团 |

最后一条是顺手挖出来的真 bug：扇形是按固定 `spread` 排的，卡片宽度却逐张递减，
**越早抽到的牌越大、盖住后面所有牌**。

### 2. 新的卡面构件

整张牌现在由七个主题化构件叠出来，全部收敛在 `theme.js`：

```
┌──────────────────────────┐
│ ◈  名称铭牌（旗形/匾额）  │  ← 费用宝石压在左上角外侧
│ ┌──────────────────────┐ │
│ │  画窗：母题水印        │ │  ← 放射光 → 主体图形
│ │  + 放射光 + 主体图形   │ │     中心聚光 + 四角内阴影
│ ├──────────────────────┤ │
│ │ ▎术法                 │ │  ← 类型绶带：色标条 + 向右淡出
│ ├──────────────────────┤ │
│ │  规则框               │ │
│ │  描述文字             │ │
│ │            ✦          │ │  ← 稀有度刻印（rare 金印放射 / uncommon 银环）
└──────────────────────────┘
```

| 构件 | gothic | shanhai |
|---|---|---|
| 卡片形状 | 圆角 + 荆棘卷草角饰 | **方角 + 青铜回纹角饰** |
| 铭牌 | 燕尾**旗形** | 两端云头的**匾额** |
| 画窗 | 中心聚光 + 月晕母题 | 中心聚光 + 印章方胜母题 |
| 费用宝石 | 八边切面 + 暗金环 | 八边切面 + 青铜环 |
| 稀有度 | 金印（8 道放射光）/ 银环 | 鎏金印 / 铜绿环 |
| 遗物章 | 圆形勋章 | **八边牌形章**（青铜器形制） |

选中的牌是**金色描边 + 外扩光晕 + 抬升**，不再是「整张卡降透明度」。

### 3. 卡面版式是算出来的，不是画出来的

卡面尺寸有 9 档（116~300 逻辑宽），死守固定版式必然在某一档炸掉。
`cardLayout(w, h, descLines)` 用**底部锚定**解决：

- 规则框贴着卡面下沿往上长，高度按文字行数算
- 绶带压在规则框上面
- **画窗吃掉剩余空间**，有 `0.48w` 的下限
- 文字太长时先压字号（下限 8px），宁可字小也不让字掉到框外

结果：**描述越长，画窗越小**。1 行描述的牌有一整块插图区，
3 行描述的牌画窗缩到下限但文字仍然完整。

### 4. 战斗界面也统一到同一套材质

之前顶栏是两块写死的 `0x14101c` 色块，行动力/灵韵是两个裸圆圈，
敌人血条和玩家血条长得一模一样。现在：

- **顶栏 / 行动条** 走 `drawChromeStrip` —— 和卡面共用材质，
  东方篇自动带上回纹端头
- **行动力 / 灵韵宝珠** 走 `drawOrbBase` —— 八边切面 + 暗井 + 金属环 + 槽位高光
- **血条** 走金属框 + 暗轨 + 填充 + 顶部高光 + 前沿刻线
- **状态徽章 / 意图图标 / 遗物章** 全部换成卡面材质

### 5. 实现约束

- Phaser Graphics **没有真正的渐变填充**。「渐层」用同心矩形叠加的聚光逼近
- **没有 Canvas2D 的曲线 API**。卡面绘制函数的 `g.*` 调用被静态扫描测试覆盖，
  出现 `quadraticCurveTo` / `bezierCurveTo` 会在测试里直接失败，
  而不是等到抽到那张牌才炸在运行时
- 卡面的全部构件画在**同一张 Graphics** 上，Phaser 合成一次绘制调用，
  5 张手牌的移动才不会掉帧

## 四、战斗舞台与交互手感（v4）

这一版不加内容，只修两件手感事：**对手浮在半空**，和**点起来不跟手**。

### 1. 为什么对手会「浮在半空」

之前敌人是一张立绘按 `setOrigin(0.5)` 居中贴在立面背景前面，脚下什么都没有。
只要一个角色脚下没有「落点」，无论立绘多好看，读出来都是飘着的。

判定一个角色有没有站在某处，靠的不是平台本身，而是**三样东西同时出现**：

| 要素 | 作用 | 缺了会怎样 |
|---|---|---|
| **地平线** | 地面从哪一条线开始 | 观众找不到「站在哪一面」 |
| **透视台座** | 被压扁的椭圆 / 梯形，是有厚度的平面 | 角色像贴纸浮在背景上 |
| **接地阴影** | 脚底那个又小又深的椭圆 | 台座变成传送门，不是地板 |

少任何一样都会穿帮，所以三者绑成一组，坐标集中在 `ui.js` 的 `STAGE` 里，
**特效锚点也全部从写死的 y 值迁到 `_fxEnemyY` / `_fxPlayerY` 两个辅助函数**。
以前立绘一挪，伤害数字就飞错位置，而且两个错误互相抵消、截图上完全看不出来。

相机高度定在地平线略上方，俯角约 12°，于是敌人在地平线处最远、玩家在画面下方最近。
**「远小近大」是透视唯一不可省的那条规则**，所以：

```
敌方台座 DAIS_RX = 250   （圆椭圆，rx:ry ≈ 3.8:1）
玩家近景台 APRON_HW = 470 （上窄下宽的梯形踏面 + 侧壁厚度 + 沿口高光）
```

玩家那一侧的台面**必须更大**，形状也从圆椭圆换成方台。尺寸差和形状差一起，
才撑得出纵深。这条不变量已经写进测试（`[战斗舞台]` 段）。

台座先画侧壁（`horizon + lift*0.5`）再画顶面，两者的高差就是「厚度」；
台沿高光只画上半圈。`drawContactShadow` 的 `strength < 1` 预留给悬浮单位
（相柳、帝江），它们本来就不该有实打实的接地阴影。

其余配套调整：

- **敌人 HP 条移到台座前缘之下**（`ENEMY_HP_Y`），不再压在脚上
- **玩家侧删掉原来的硬边矩形**，改成「近景台 + 接地投影 + 头像」，
  用现有素材讲出「我站在这」；没有玩家立绘就不做过肩视角
- **牌堆移出手牌区**（`PILE_LX / PILE_RX` @ `PILE_Y`）：
  行动条 106px 的缝隙放不下 84px 的牌背，压在两侧更干净

### 2. 交互手感

选中这一段保留点选，**出手那一段在这一版换成了上滑**（见本节第 10 条），
但选中本身的反馈先补齐：

- **自定义光标**（`CURSORS`）——内联 SVG data URI，不新增素材文件。
  Phaser 默认一个光标都不设，于是鼠标下所有可点的东西跟不可点的背景长得一模一样，
  玩家会反复去点不可点的地方，这是「鼠标效果」最刺眼的一处缺失
- **按钮四态各画各的**（idle / hover / press / off），不用改 alpha 糊弄：
  alpha 会把描边和文字一起洗淡，看起来像「坏了」而不是「亮了」
- **首触反馈**——第一次按下必须有反应，否则玩家以为没响应就连点两下直接出牌
- **提交时机从 `pointerdown` 改到 `pointerup` + 位移校验**（`SLOP`），
  根除「滑动也出牌」
- **选中时其余手牌压到 0.62**，不可打出用 `deny()`（牌自己横弹 + 红边），
  不用全屏 shake——点一张打不出的牌，整块屏幕跟着晃一下，观感像程序出错
- **出牌改成飞行动画**，攻击牌飞向敌人、辅助牌飞向玩家自己，替代 `destroy()`
- **结束回合时手牌逐张错开 34ms 飞向弃牌堆**，给出明确的「你点的生效了」
- **按钮禁用时文案改成「敌 方 行 动」**——玩家只知道自己点不了，不知道要等多久

有两个坑值得单独记一笔：

- `armed` 标志用来区分「确实看到过这一次按下」和「只收到抬起」。
  没有它还去算 dx/dy，就会拿初值 0 当基准，**任何点击**都被判成
  从屏幕原点滑过来，于是静默失效——这种失败没有任何表现，最难查
- 悬停状态自己记（`hoverOn`），**不要读 `c.input.hovered`**——
  Phaser 没有这个属性，读它恒为 `undefined`，松手后按钮会错误地缩在放大态

### 3. 顺手修掉一个会毁掉整场战斗的 bug

`endTurn` 之前只做了 `S.hand = []`，**没把手牌牌号搬进 `discardPile`**。
后果是每回合 5 张牌从游戏状态里永久消失：不进弃牌堆，也就永远洗不回抽牌堆，
打两三个回合抽牌堆就见底，之后每回合只能抽 1~2 张。而界面上的弃牌堆计数一直是 0，
玩家完全看不出牌去哪了——只觉得「牌越打越少」。

修法是把牌堆循环抽到纯逻辑层，`core/combat.js` 新增两个函数：

```js
discardHand(hand, discardPile)   // 回合结束：手牌整副进弃牌堆
drawOneCard(drawPile, discardPile, shuffle)  // 抽牌；空了自动洗回弃牌堆
```

场景层只管播动画，算账交给纯逻辑层——这和伤害公式是同一套做法。
`[牌堆循环]` 测试段钉住了「洗多少轮牌库总数都守恒」这条不变量。

### 4. 一个关于「验证」的诚实说明

排查过程中发现，**内置浏览器的 `click` / `drag` 动作无法可靠地派发完整的
按下-抬起序列**（`drag` 的返回值里 `dropDispatched: false`；同一操作两次
点击的行为不一致）。Phaser 的对象级事件依赖 `mouseup`，所以在这些动作下
**任何可点元素都会看起来"没反应"**。

这个坑一度让我以为按钮代码坏了。最终用两种方式绕开：

- 用 `press_key` 走键盘通路验证回合流程（它的事件通路是独立的，稳定）
- 把交互规则写成**纯逻辑断言**（牌堆守恒、舞台透视不变量、光标串转义），
  让测试去钉住，而不是靠肉眼看截图

**结论：出牌/点按钮的手感，真机上你实际点一次才算数。**
自动化只能证明「命中区算对了、事件通路存在、状态机守恒」，证明不了「手感顺」。

### 5. 开场那 420ms，三处 UI 停在「构造默认值」

`startPlayerTurn` 挂在 `delayedCall(420)` 上（要给开场一个「准备」的呼吸），
但 `create()` 当帧就已经把整块画面画完了。差的这 420ms 里，画面上是
`build*` 刚 new 出来的原始状态，而不是 `refresh*` 刷过之后的状态：

| 位置 | 修之前 | 修之后 |
| --- | --- | --- |
| 顶栏回合 | 「回合 0」（像计数坏了） | 「准 备 中」 |
| 行动力 | 裸文字 `3/3`，宝珠没画 | 六边形宝珠正常 |
| 灵韵计 | 哥特篇闪出一个「灵韵 0/3」 | 整条隐藏 |
| 结束回合 | 长得完全可点，点了没反应 | 灰色禁用 + 「准 备 中」 |

最后一条才是真正会被玩家骂的：`endTurn` 有 `S.busy` 守卫，不会出漏洞，
但按钮外观在骗人。现在 `startCombat` 里先把 `refreshEnergy()` /
`refreshHandState()` 跑掉，再排那个 420ms；灵韵三个对象也改成构造即隐藏，
可见性只由 `refreshEnergy()` 决定。

### 6. 一次性动作全都缺闸门

「点了会怎样」和「点两下会怎样」是两件事，这一轮揪出四个地方只做了前者：

- **`pickRelic`** —— 遗物层要 280ms 才淡出销毁，这中间整层都还活着。
  连点两下（或键盘 `1` 紧接着按 `2`）会把**两件都收走**。
  `addRelic` 只挡「同一个 id 重复」，两件候选本来就不一样，拦不住。
- **`goNext`** —— 连点「继续」把 `RUN.advance()` 跑两遍，**凭空跳掉一个地图节点**，
  而且两个 `scene.start` 会一起排队飞出去。
- **`startRun`** —— 手机上「开始征途」连点两下，Combat 被 stop/start 两遍。
- **数字键长按** —— 一次按键打一张，长按的 `repeat` 会连打好几张，桌面测试没法用。

修法统一成一个 `if (this._xxx) return;` 的一次性标记，并且**必须同时在
`create()` 里初始化**——否则闸门是 `undefined`，第一下照样穿透。
（`showRelicChoice` 里也要复位，因为它是唯一会重开遗物层的地方。）

### 7. 弹窗盖住了按钮，但没挡住按钮

`showHelp` / `showConfirm` 只是「往上盖了一个 container」。可 Phaser 的
Graphics 不吃点击，**面板底下那两个按钮照样能按到**。

帮助面板覆盖 y 300~1620，正好把「开始征途 / 怎么玩 / 重新开始」全罩在下面。
玩家在面板上半部分随手一点就直接开打；有存档时更糟，按到「重新开始」那块会
反反复复弹确认框。

修法是铺一层全屏可点的遮罩，压在面板之下（depth 49）、菜单之上（depth 4）：
面板自己的按钮在 50 照常可点，面板之外的点击全被吃掉。顺手当暗化背景用。

### 8. 数字键解析三处不一致

`/^Digit([1-9])$/` 只认主键区。小键盘的 `e.code` 是 `Numpad1`、部分输入法
布局下 `e.code` 干脆不给——两种都收不到。CombatScene 上一轮改了，
EventScene 和 RewardScene 还停在老写法。现在三处统一：
`/^(?:Digit|Numpad)([1-9])$/` + `e.key` 兜底 + `if (e.repeat) return;`。

### 9. 事件里当场拿到的遗物，顶栏不刷新

遗物条是 `buildTopBar` 里就地搭的一次性容器，`pick()` 拿到新遗物后只重刷了
生命和金币，顶栏就一直挂着「尚无遗物」——玩家明明刚拿到「骨髓药瓶」。
抽成 `refreshRelicBar()` 挂进 `refreshTop()` 就好了。事件是全程唯一会
**当场**发遗物的场景，所以这条路径必须能重画。

这五条都补进了 `[一次性闸门]` / `[弹窗与开场态]` 两个测试段。闸门全在
Phaser 场景方法里，没有浏览器就求值不了，所以这些断言读的是**源码**——
至少能钉住「闸门不许被删」，防止以后重构时无声拆掉。

### 10. 点了牌之后，怎么把它打出去

这是这一版唯一的新交互。之前的流程是**两段式点选**（点一次抬起、再点一次打出），
两段式本身没错，错在**第二段没有任何东西告诉玩家**：牌抬起来了、金边出来了，
然后呢？不知道。实测里这是最容易被骂的一条——玩家会以为点不动，转而去戳别的地方。

#### 三条并行的出牌路径，不是三选一

第一段点选保留（防误触），第二段给出**三条并行**的出口：

| 路径 | 适合 | 实现 |
|---|---|---|
| **按住上滑，松手打出** | 触屏 | `PLAY_SWIPE` 阈值 + 场景级 `pointermove` 记账 |
| **点提示条** | 网页版 | 提示条自带 `setInteractive` 矩形命中区 |
| **再点一次选中的牌** | 网页版 | `selectCard` 里 `S.selected === card` 分支 |

三条都在，是因为**只留一条就等于给另一半用户留了个死胡同**：
只留「上滑」时，网页版用鼠标甩不动这张牌（用户实测反馈「无法上滑出」）；
只留「点击」时，触屏上少了一条最自然的手势。删掉任何一条都算回归。

提示条的文案和图标**跟着当前设备走**：触屏显示「▲ 上滑打出」，
鼠标显示「◎ 点击打出」——图标得跟玩家实际在用的那条路对上，
否则鼠标用户看到一条写着「上滑」的提示会直接跳过它。

> 命中区比可视高度高 18px（76 vs 58）。提示条是玩家唯一的「打出」入口，
> 58px 在手机上够不到 44pt 触控目标下限。隐藏时必须同时
> `input.enabled = false`——alpha 0 的 Graphics 在 Phaser 的
> `pointWithinHits` 里照旧参与命中，一条看不见的条子会挡在牌上面。

#### 两个常数：行程和视觉解耦

```js
PLAY_SWIPE = 120   // 手指上滑多少像素算「打出」，约屏幕宽 11%
PLAY_LIFT  =  56   // 卡实际往上走多少像素
```

120px 的依据：拇指误触的位移普遍在 30px 以内，**留了四倍余量**；
再大就要求玩家「特意」去滑，仪式感太重。

为什么视觉只上移 56px？因为手牌顶边离玩家血条只有 **90px 净空**，
卡要是真跟着手指走满 120px，会直接盖住自己的血条。**手指行程 ≠ 卡片位移**，
这条必须解耦，否则「提示做得很到位」的结果是「自己的血看不见了」。

#### 提示条：挂在牌的上沿，不悬空

上方净空放不下一个悬空的提示框，所以提示条**压在牌的上沿**，
用两个场景级对象拼（`hintG` 画板 + `hintT` 写字），和行动条里
`energyG` / `energyText` 是同一套写法。两个状态：

| 状态 | 外观 | 文案 |
|---|---|---|
| 未就绪 | 暗底 `0x2a2236` + 金边 + 底部进度条随上滑填充 | ▲ **上滑打出** |
| 已就绪 | 整条实心金，箭头翻成深色 | ▲ **松手打出** |

**文案翻面是关键**——玩家不需要去读那条进度条就知道现在松不松手。
颜色只做辅助，因为「这条条子亮了」是比「这五个字变了」弱得多的信号。

> 踩过的坑：这个提示条最初做成 `Container + Graphics + Text`，
> 位置、`visible`、`alpha`、depth 全都正确（容器确实在 (538, 1214)，
> `list` 里有 2 个子对象），但**一行都不画**，换成洋红 `fillRect` 同样不渲染，
> 而同场景的 CardView 容器一切正常，控制台零报错。差异没查到底，
> 不拿一个「看起来对但可能还有坑」的写法冒险，直接换成两个场景级对象。

#### 拖拽记账必须在场景层

这是整个手势能不能成立的技术前提，有三条 Phaser 行为必须绕开：

- **牌的 `pointermove` 在手指滑出上沿时就断了**。Phaser 会发 `pointerout`，
  并且不再给这张牌 move 事件——而那正是「要把牌打出去」的那一段。
  所以拖拽进度不能挂在牌上，**由场景级的 `pointermove` 跟到底**（`this._drag`）
- **手指滑出牌面后 Phaser 不再发 `pointerup`**，只发 `pointerupoutside`。
  只监听 `pointerup` 的话，甩到牌外面松手会卡在「一直举着」的状态
- **触摸下连 `pointerupoutside` 都收不到**。用 CDP 合成触摸事件实测：
  手指上滑过阈值、提示条翻成「松手打出」，抬起后牌被选中了，
  但 `_drag` 仍然挂着 `armed:true`——**指针事件压根没回到牌上**。
  鼠标路径侥幸能用（鼠标会派给 `pointer._wasOver` 里的对象），
  真机上这条手势会直接失灵

第三条的修法是**场景级 `pointerup` 再兜一份**：

```js
const dg = this._drag;
if (dg && dg.id === p.id && dg.card && dg.card._releaseSwipe) dg.card._releaseSwipe(p);
```

场景级 `pointerup` 对每根手指都会来一次，不依赖任何命中测试。
`bindCardInput` 把自己的 `release` 挂到 `cv._releaseSwipe` 上——
**存引用而不是再写一遍收尾逻辑**，两份逻辑迟早走偏，
闸门只有一个（`pressing`）才收得住，谁先跑到谁收尾。

还有两条：

- **拖起来就自动选上**（不管之前选没选），
  让「按住直接甩」和「先点再滑」走同一条通路，玩家不用先学会两步
- **`release` 的 `!pressing` 分支要清 `_drag`**。触摸下浏览器会补发
  `pointerdown`，收过尾之后 `_drag` 可能被重建；留着会让下一次抬手
  带着一条陈旧的拖拽记录，起点还是上一次的位置

#### 键盘一次出一张

桌面端用鼠标拖拽本来就是反人类的。`1`-`9` 改成**一次按键直接打出一张牌**，
不再走「先选中」。顺带把选中牌提到 depth 260，
否则后一张牌会盖住它、连带把上滑手势也吃掉。

#### 验证结果

用 Playwright 驱动真实 Edge 跑，三条路径 + 触摸通路全部实测：

| 检查 | 结果 |
|---|---|
| 点提示条 | 敌人 27→21、行动力 3/3→2/3、弃牌堆 0→1 |
| 再点一次选中的牌 | 敌人 21→15、行动力 2/3→1/3、弃牌堆 1→2 |
| 触摸上滑过阈 | `armed=true`，文案翻成「松手打出」，模式 `touch` |
| 触摸松手出牌 | 手牌 5→4、行动力 3→2、弃牌堆 0→1，`_drag` 已清 |
| 隐藏的提示条不挡牌 | 无选中态时点牌能正常选中 |

`[出牌手势]` 段 25 条断言钉住阈值区间（100~160）、`lift < swipe`、`lift ≤ 60`、
提示条建/显/隐/命中区三件套、三条出牌路径都必须在、
场景级 `_releaseSwipe` 兜底、`!pressing` 分支清 `_drag`、
以及中途加牌不许换尺寸。

## 五、玩法

### 核心循环

每回合 3 点行动力，抽 5 张牌，打出牌或结束回合 → 敌人按预告行动 → 下一回合。

### 意图预告

敌人头顶的图标 + 数字就是它下回合要做的事，**和实际结算共用同一套伤害公式**，
所以显示的数字永远等于你挨的伤害。

| 图标 | 含义 |
|---|---|
| 剑 + 数字 | 攻击，数字是总伤害 |
| 盾 | 防御 |
| ↑ | 强化自己 |
| 骷髅 | 削弱你 |
| 毒 | 施毒 |
| 火 | 灼烧 |
| 瓶 | 吸血 |
| 心 | 治疗 |

### 状态

| 状态 | 效果 |
|---|---|
| 力量 | 攻击伤害 +N（永久） |
| 易伤 | 受到伤害 +50% |
| 虚弱 | 造成伤害 −25% |
| 脆弱 | 获得格挡 −25% |
| 中毒 | 回合开始失去等量生命 |
| 灼烧 | 同中毒（东方篇意象） |
| 尖刺 | 受击时反弹伤害 |
| 燎原 | 受到的每次攻击 +N（永久） |

### 灵韵与符箓

- 灵韵每回合 +1，上限默认 3（`青铜盏` +2，事件可永久提升）
- 符箓牌只吃灵韵，不吃行动力
- **共鸣**：本回合每打一张符箓，后续符箓费用 −1（最低 0）
- 灵韵条只在东方篇显示（`THEME.spiritLabel = null` 表示不显示）

### 构筑

每场战斗后可选：拿 1 张牌（三选一）/ 跳过。遗物永久生效。
事件节点提供删牌、换牌、拿遗物、付代价的强取舍。

**遗物 14 件**：9 件哥特 + 5 件东方，分世界掉落（见上文第 7 节）。

### 战后恢复

战斗胜利后按比例回血：普通战 **26%** 生命上限，精英 / BOSS 战 **42%**。
满血时不会溢出。这是平衡复利衰减的关键机制——详见上文第 9 节。

### theme.js 的绘制函数分三类

| 类别 | 函数 | 用在哪 |
|---|---|---|
| 面板 | `drawPanel` / `drawMotif` / `drawDivider` | 事件页、奖励页、标题页、按钮 |
| **卡面** | `cardRadius` / `cardLayout` / `drawCardShell` / `drawArtWell` / `drawNamePlaque` / `drawTypeBanner` / `drawRulesBox` / `drawCostGem` / `drawFoilSeal` / `drawCardCorners` / `drawWellLight` / `drawRays` | 37 张卡全量继承 |
| **界面构件** | `drawChromeStrip` / `drawOrbBase` | 顶栏、行动条、行动力宝珠、灵韵宝珠 |

`CARD`（卡面材质）是**第四个**「共享可变对象」，和 `PAL` / `FONT` / `TYPE_STYLE` 一样
被 `applyTheme()` 原地改写——所以「换皮只改一个文件」这个性质在卡面上同样成立。

### 主题层为什么用「共享可变对象」

`PAL` / `FONT` / `TYPE_STYLE` / `CARD` 都是 `const` 声明的**可变对象**，
`applyTheme()` 用 `Object.assign` 原地改写。这样**不需要为了换皮重构 1000+ 行场景代码**——
风险最低、覆盖最全。代价是主题不能「局部生效」，但本作是整屏换皮，正好合适。

### 战斗算式为什么抽到 `core/combat.js`

因为离线模拟器要跑 3000 局并**读同一批数据文件**。
算式留在场景里，模拟器就得抄一份，抄的那份迟早和真实游戏跑偏——**测出来的曲线是假的**。
抽成纯函数后，模拟器和实际游戏跑的是同一份代码，结论才可信。

### 平衡模拟器

```powershell
node tools\simulate.js 3000
```

`tools/simulate.js` 让一个贪心 AI 用真实的卡池 / 敌人脚本 / 事件 / 遗物连打 N 局，
输出逐战到达率、通过率、阵亡分布。它与 `CombatScene` **共用 `core/combat.js` 的算式**，
所以它的结论对真实游戏有效（见第 7 节的架构理由）。

```powershell
node tools\simulate.js 3000 --chapters=3                    # 对照实验
node tools\simulate.js 1500 "--hp=forest_lord:76,84;dijiang:120,128"   # 沙箱内调参
```

`--hp=id:lo,hi` 在沙箱内覆盖血量，**不改源码**——
反复改文件跑对照是脏且容易忘了改回去的。

## 十、诚实的边界

这一版做到的：

- 18 战双世界完整流程，事件 / 奖励 / 战斗三套场景全部走通
- 主题层让换皮只改一个文件，**实测卡面、按钮、面板、血条、宝珠、遗物章全部跟着切**
- 卡面从「一块深色矩形 + 几行小字」重做成七构件体系，
  两套主题的形状、材质、铭牌形制、遗物章形制全部不同
- 灵韵 + 共鸣是有真实决策的机制，不是数值装饰
- 14 件遗物全部可用，5 件东方件把新资源线接进构筑框架
- 16 张原创立绘 + 2 张背景
- **8673 条逻辑断言全绿**
- **18 战难度曲线由 3000 局模拟实测**，不是拍脑袋；模拟器与实际游戏共用算式

**还没做到的**：

1. **真机触屏仍未验证**。触摸通路我用 **CDP 合成触摸事件**在真实 Edge 里跑通了
   （轻点选中、小幅滑动选中、上滑过阈翻面、松手出牌，四步全过），
   这条路子确实抓到一个真 bug——手指滑出牌面后 Phaser 根本不把 touch 的
   `pointerup` 派给那张牌，鼠标路径侥幸能用是因为鼠标会派给 `pointer._wasOver`。
   修法（场景级 `pointerup` 兜底）见第四节第 10 条。
   **但 CDP 合成触摸不等于真手指**：120px 的阈值对拇指合不合适、
   拇指区布局、44pt 触控目标、竖屏安全区、真实手指的抖动和多点触控，
   都必须你在真手机上自己点一遍。这是第一优先级，我没有能力代做这一步。
2. **玩家侧没有角色立绘**。只有 16 张敌人立绘。当前用「近景台 + 接地投影 +
   骷髅头像」表达玩家位置。补一张玩家立绘后可以做近景持剑手 / 过肩视角，
   空间感会再上一台阶。
3. **平衡的绝对值仍未定论**。模拟器给的是**贪心 AI 的基准线**（全程 1.5%），
   AI 不预判意图、不主动格挡、不用集中、奖励乱选。真人通关率会显著更高。
   现在能信任的是**曲线形状**（无死区、无单点塌陷），不能信任绝对值。
4. **卡面插画已补齐**：18 个 `art` key 各有哥特、山海两版，共 36 张；37 张卡牌均覆盖。
5. **AI 合成的立绘画风未完全统一**。9 张东方立绘偏厚重墨线插画，
   与哥特篇的淡彩不完全统一；**鹿蜀的头部读起来偏骷髅**，需要重画或人工修。
6. **没有音频**。《月圆之夜》的氛围一半靠声音，目前完全是静的。
7. **没有存档续玩的 UI**。`localStorage` 存档能跑，但没做「读取存档」的显式入口体验。
8. **没有难度选项**、没有元进度、没有成就。
9. **敌人 AI 只有加权随机 + 血量阶段门槛**，
   没有真正的战术行为（比如集火、留格挡反打）。
10. **无障碍基本为零**：字号固定、色盲友好度未测、屏幕阅读器不支持。
    9 张牌时描述字号会压到 13~14px，视力弱的玩家会吃力。
11. **事件仍是纯文本抉择**，没有插图，叙事张力靠文字撑。
12. **原型级代码质量**：全局函数、无模块系统、场景之间靠全局 `RUN` 通信。
    能跑、能改，但不该直接拿去做产品基础。
