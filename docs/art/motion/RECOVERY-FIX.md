# 敌人攻击与受伤恢复修复

2026-10-11，接续主角与 UI 改版。

## 原因与复现

`MOTION.playEnemy` 在减少动态模式中停止帧动画后直接设置静态帧：攻击被设为中立帧 0，受伤设为帧 4。这个分支不产生 `animationcomplete`，因此原来依赖该事件恢复待机的逻辑永远不会执行。开启减少动态后，实际 `hitEnemy(1)` 经过 350 ms 仍停在帧 4；修复前的新浏览器用例在此明确失败。

旧的验证只检查减少动态时动画停止，没有覆盖攻击姿态和受伤后的恢复，因而漏掉了这个问题。

## 当前行为

- 普通模式继续使用完整动作帧，播放结束回到待机。
- 减少动态模式保留简短姿态提示：攻击帧 1 蓄力，160 ms 后帧 2 出手，400 ms 后恢复；受伤帧 4 保持 200 ms 后恢复；防御帧 5 保持 400 ms 后恢复。
- 减少动态仍不循环待机、不震屏、不全屏闪色；没有强行关闭玩家或系统的动态偏好。
- 每次新动作取消上一次动作的恢复计时，避免旧受伤动作提前覆盖新攻击或新受伤。计时使用 Phaser 场景时钟，暂停时一起暂停。
- 敌人死亡和 Sprite 销毁清理计时，死亡后不能被旧回调切回待机。
- 攻击数值与结算规则未变：前摇 160 ms，连击间隔 260 ms。

## 验收

`node tools/verify-motion-recovery.js` 检查全部 16 个敌人在两种模式下的攻击/受伤/防御恢复、连续反应、暂停、设置切换、死亡与销毁，以及真实点击结束回合后两次伤害结算和下一玩家回合。证据见 `RECOVERY-REPORT.json`；`attack-normal.png`、`attack-reduced.png` 是实际出手帧，`recovered-idle.png` 是受伤后恢复画面。

`node tools/verify-motion.js` 回归蓝盾、红伤、绿治疗与图集接入；`node tools/test-logic.js` 为 9127 passed / 0 failed。
