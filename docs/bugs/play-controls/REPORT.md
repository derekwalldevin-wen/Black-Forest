# 本地出牌入口修复与低频阅读入口调整

日期：2026-10-25。已接入本地源游戏；未覆盖线上版本或已发布的桌面安装包。

## 已复现的问题

1. 选中卡牌后，鼠标移出画布再移回，`gameout` 把确认提示条隐藏，但 `state.selected` 仍保留。窄屏玩家因此看不到确认入口。
2. 点确认或松开上滑手势时，输入层先隐藏提示条，再调用 `playCard`。资源不足会被结算层拒绝，卡牌留下，按钮却没有恢复。
3. 快速关闭难度弹窗时，Phaser 的暂停操作尚在队列中，`isPaused()` 仍为假。旧关闭逻辑跳过恢复，下一帧反而留下一个已暂停的场景，造成开局等待。相同的已知暂停配对风险也在手牌阅读和教学中修复。

修复前的实际浏览器事件与状态见 `baseline/verification.json`，包括两项失败及浮动手牌入口存在的记录。修复后的同类检查与扩展流程见 `fixed/verification.json`。

## 修改

- 指针移出、失焦与场景恢复统一清理手势；卡牌保持选中时恢复确认按钮。中断手势清理按压状态，不提交或扣费。
- 难度、手牌阅读与教学的暂停 / 恢复按所有权成对入队；难度确认等恢复发生后再回调建局。补充同一帧内开关弹窗后跨三帧的状态验证。
- 输入层不再提前隐藏确认入口；只有成功提交的 `playCard` 负责隐藏。费用不足保留卡牌、选中状态与资源不足说明。
- 资源更新后刷新选中卡牌的按钮状态。桌面右侧说明与状态单独滚动，确认区固定在底部。
- 删除战斗画面上的浮动“手牌一览 · H”。窄屏使用菜单内的“手牌一览”；桌面阅读工具位于默认折叠的“操作提示与快捷键”内。H 快捷键仍可用。
- 阅读关闭后将焦点还给游戏画布，保留查看与出牌的区分。选牌不会在关闭阅读界面时自动打出。
- 更新相关 CSS / JS 的入口缓存版本，以及受入口迁移影响的已有验收脚本。

## 验证与边界

- `node tools/verify-play-controls.cjs`：真实浏览器鼠标离开返回、按压后中断、费用不足拒绝、资源恢复后确认、菜单阅读、H、数字键出牌、触屏点选与确认；中英文桌面覆盖 1040 × 560 与 1280 × 720，包含滚动后确认区仍在视窗内的断言。
- `node tools/verify-card-input.js`：真实双击出牌、动画清理、过期提交与费用拒绝、回合切换通过。
- `node tools/verify-r2-ui.cjs --functional --out=docs/bugs/play-controls/r2-regression`：桌面、阅读和教学的既有八组操作回归。当前证据独立保存在 `r2-regression/`，原 R2 发布证据保持原样。
- `node tools/test-logic.js`：9238 passed / 0 failed。旧 `gameout` 断言曾依赖回调内联的文本顺序，现改为执行真实恢复函数并检查拖拽、指针和确认状态。
- `node tools/test-localization.js`：43 张卡牌本地化通过。新增菜单文字覆盖中英文。
- `node tools/verify-difficulty.cjs`：复核上一轮美术界面的中英文布局、三档开局和存档；最终结果见 `docs/ui-difficulty/evidence/verification.json`。

浏览器触摸模拟和视窗尺寸检查不代表实体手机、操作系统缩放或新打包桌面程序已经验收。本次确认修复上述已复现原因，不声称整个游戏不存在其他问题。
