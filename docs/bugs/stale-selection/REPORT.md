# 选中卡牌跨回合后无法出牌

2026-10-25，直接读取用户正在卡住的本地页面确认。不是资源不足。

## 现场与根因

现场是第五章蜚战斗的第二回合，行动力 3、灵韵 3。右侧仍显示“血月”，但当前五张手牌中没有血月；点击新牌会在 `CardView.setSelected → _build → setInteractive` 抛出 `Cannot read properties of undefined (reading 'sys')`。现场图片与错误堆栈保存在 `live-before.png` 和 `live-errors-before.json`。

`endTurn()` 原来先设置 `S.busy = true`，再调用 `selectCard(null)`。后者会因 busy 提前返回，导致旧的 `S.selected` 未清空。回合结束的动画随后销毁旧 CardView，下一回合再选牌时，程序试图取消这张已销毁的牌并重建它，输入操作便持续报错。旧对象与新手牌即使牌名相同，也不是同一个 CardView。

独立测试用完整回合流程复现了同样问题：`baseline/verification.json` 显示下一回合行动力 3、灵韵 2，选中对象不在手牌中、已被销毁，再点击新牌出现相同异常。上一轮出牌按钮检查没有覆盖“选中但未打出就结束回合”，所以没有发现它。

## 修复

- 结束回合先清理选中，再锁输入和弃牌；开始新回合再清理一次。
- 取消选中属于生命周期清理，允许在 busy 期间执行；仍禁止忙碌时选择新牌或支付出牌。
- 场景统一检查卡牌是否属于当前手牌、容器是否存活、是否正在退场。过期引用不能被选中、提交、显示确认提示或启用桌面出牌按钮。
- `CardView.setSelected()` 拒绝重建已销毁或退场中的对象，避免迟到的手势触发相同异常。
- 更新入口脚本缓存版本为 `20261025-turn-selection`，旧页面需要刷新加载。

## 验证

`node tools/verify-turn-selection.cjs` 覆盖中文桌面哥特、中文窄屏哥特、英文桌面山海、英文触屏模拟山海。每组连续两次选择未打出的牌后结束回合，等待真实敌人行动和新手牌，再分别支付行动力与灵韵打牌，共 8 次回合切换、16 次确认出牌。检查按对象身份清除旧选中、旧容器已销毁、资源按实际费用扣除、卡牌成功离手，且没有页面异常。证据见 `fixed/verification.json` 和实景图。

另复核既有真实卡牌输入与按钮/阅读/弹窗恢复检查，以及 9238 条逻辑和 43 张卡牌本地化。浏览器触屏模拟不等同于实体手机验收。本次修改在本地源游戏生效，未发布 GitHub Pages 或重打桌面安装包。

## 原页面复核

在用户原来的本地页刷新修复脚本，从既有第五章存档继续本场战斗，选中“血月”但不打出后结束回合。第二回合没有旧选中，随后通过真实界面依次打出“封门”（灵韵 4 → 3，格挡 2 → 10）和“盾击”（行动力 3 → 2，格挡 10 → 15），手牌从 5 张降至 3 张。保留同一征途存档，当前战斗已恢复可操作。

`live-after.png`、`live-after.txt` 和 `live-verification.json` 为原页面复核证据。浏览器日志接口保留了刷新前的错误，因此 `live-errors-after.json` 仍含历史条目；对比现场最后一次错误时间，没有新增错误，不能把旧条目误称为修复后又报错。
