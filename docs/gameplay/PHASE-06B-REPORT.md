## 0. 结论

**任务书批准的三个杠杆，全部叠加后仍然不足以让三套菜单传承达到工程门槛。
因此本轮没有把任何候选接进运行版，游戏数值一行未改。**

选参批次（300 局/臂）里 `values+floor+energy` 以 3.0pp 通过；
但任务书要求「用**未参与选参数**的独立种子批次，每臂至少 1000 局确认选中的候选」——
**该组合在独立批次上是 5.3pp，超门槛。没有任何组合通过。**

这正是任务书第 151 行预留的那种情况：

> 候选若把三种传承都变成几乎无法推进，或符咒变成没有选择的等待，不算通过。

本轮不是这两种失败，而是第三种：**候选不够**。
缺口从选参批次的 3.0pp 变回独立批次的 5.3pp，
且符咒仍然**统计上显著领先**（配对 p=0.0004），不是噪声。

## 3. 确认批次（1000 局/臂，独立种子）—— 关键结果

| 组合 | classic | blood | guard | talisman | 通关差 | 最佳 vs 最差配对 |
|------|--------:|-------|-------|----------|--------|------------------|
| baseline | 25.6% | 29.4% | 25.9% | 41.3% | 15.4pp 超 | 202/52，p<0.0001 |
| values | 24.2% | 29.0% | 25.4% | 38.2% | 12.8pp 超 | 187/59，p<0.0001 |
| floor | 24.1% | 28.7% | 24.3% | 39.3% | 15.0pp 超 | 202/52，p<0.0001 |
| values+floor | 23.2% | 27.2% | 23.5% | 34.4% | 10.9pp 超 | 178/69，p<0.0001 |
| energy | 24.6% | 27.9% | 24.7% | 32.6% | 7.9pp 超 | 133/54，p<0.0001 |
| values+energy | 23.3% | 27.5% | 24.3% | 31.0% | 6.7pp 超 | 144/77，p<0.0001 |
| floor+energy | 23.3% | 27.0% | 23.3% | 29.2% | 5.9pp 超 | 127/68，p<0.0001 |
| **values+floor+energy** | 22.5% | 25.7% | 22.4% | 27.7% | **5.3pp 超** | 134/81，**p=0.0004** |

**两个批次都做的三项门槛里，「平均完成战斗数差」始终通过（0.83~1.55 ≤ 2），
「过第九战率差」除 baseline+floor 外也都在门槛内。
卡住的是「完整通关率差」这一项。**

而这一项在最好的组合上，配对检验给出 **p=0.0004**——
符咒在这批种子上真的多赢 134 局、少赢 81 局。**5.3pp 不是噪声。**

## 4. 为什么选参批次会骗人

| 批次 | 组合 | 通关差 | 结论 |
|---|---|---|---|
| 选参 300 局 | values+floor+energy | 3.0pp | 通过 |
| 确认 1000 局 | values+floor+energy | 5.3pp | 超 |

1000 局下 p≈0.28 的比例，Wilson 区间半宽约 ±2.7pp；
「最佳臂减最差臂」的差值本身还要再叠加两臂的不确定度。
所以**边缘值在小样本上极易落到门槛内侧**。

这就是任务书为什么要求独立批次，而不是简单加大选参批次的局数：
加大同一批种子只会让过拟合更稳定。

**同时要承认另一半**：8 个组合里选一个，在 8 次抽样里挑最好的那次，
本身就是「把大量候选中最好的一次抽样当最终结果」——
任务书第 147 行明令禁止的做法。本轮直接撞上了这个坑，
而不是靠加大局数绕过去。

## 5. 缺口来自哪里（本轮不做，只给证据）

三个杠杆全部作用于**单张符箓的数值与费用**。符号牌组相对其它两套还有两处
**结构上**的差异，这三条杠杆都碰不到：

| 结构差异 | 说明 | 三个杠杆是否覆盖 |
|---|---|---|
| 灵韵可跨回合累积 | 行动力每回合固定 3；灵韵每回合 +1 且**保留**，攒满后每回合实际资源 > 3 | **否**（任务书明确「保留灵韵积蓄」） |
| 共鸣让连打更便宜 | 玄玑→符纸(减费)→玄玑，形成自我加速 | **部分**（`floor` 只设下限 1，不取消递减本身） |
| 符箓牌数量 | 初始 8 张里 3 张是符箓，其余两套只有 0 张 | **否** |

按 6A 报告的消融：**符纸 + 封门几乎解释了全部差距**，
而这三个杠杆确实都作用在它们身上——只是把 10pp 压到了 5.3pp，**没有压到 5pp 以内**。

> 需要提醒：任务书第 13 行写「保留灵韵积蓄、默认上限 3、自然恢复 1」。
> 如果要继续收敛，最大的单点很可能是灵韵的跨回合累积，
> 但那是**已决定保留**的机制，改它等于推翻既有设计决定。
> **这一步应由设计侧决定，本轮不自行推进。**

## 9. 附：本轮堵掉的一个方法论漏洞

实验台第一版会**直接在选参批次里报「唯一通过的组合」**。
那正是任务书第 147 行禁止的「把大量候选中最好的一次抽样当最终结果」——
8 次抽样里挑最好的一次。而且它确实翻车了：

```
选参 300 局 → values+floor+energy 通关差 3.0pp，「通过」
独立 1000 局 → 同一组合 5.3pp，不过关
```

所以现在强制两段式，把「先定候选、再用独立种子验证」从流程约定变成工具强制：

```
node tools\phase6b-lab.js --games=300 --batch=select --seed-base=0 \
    --declare=docs/gameplay/PHASE-06B-CANDIDATE.json      # 写预登记单

node tools\phase6b-lab.js --confirm --games=1000 --seed-base=1   # 只认单上那一个
```

| 约束 | 实现 | 实测 |
|---|---|---|
| 预登记单一经写出不可覆盖 | `flag: 'wx'` | 重复写单报 `EEXIST`，退出码 1 |
| 确认批次只跑单上的候选 | `plan = [hit]` | 输出只有 `values+floor+energy` 一组 |
| 没有预登记单就不能确认 | 读不到单则 `exit(2)` | 退出码 2 |
| 未通过必须非零退出 | `process.exit(verdict ? 0 : 1)` | 本轮退出码 **1** |

这四条已加进 `test-logic.js`，以后有人把两段式改回一步到位会直接测试失败。
