# 检查点存储

当前落地的是网页适配器，不是桌面文件存档。接口在 src/core/save-store.js；RUN 负责解析/校验与迁移，SAVE_STORE 负责主备槽读写及可见错误。

## 网页行为

- 主键保持 `darkforest.run`，旧玩家可继续读取；备份为 `darkforest.run.backup`。
- 保存前仅将校验通过的旧主档写入备份，再提交新主档。备份写入失败则不改主档；主档写入失败则主备仍可保留有效的旧检查点。每个 localStorage setItem 是单键提交，两个键并非联合事务。
- 主档缺失或损坏时读取有效备份并提示可能回退一个检查点；不会把损坏主档复制到备份。双方损坏时保留原数据并显示警告。
- 高于当前 schemaVersion 的主档不降级读取或自动覆盖。确认新征途时才显式清除两槽；权限拒绝时不继续清档建局。
- 清档先删除备份，再删除主档，避免通关清档后残留备份被恢复为未完成征途。失败会提示。
- 旧档缺字段时从新局默认值补齐，不继承内存中另一局的金币、状态、遗物或剧情。
- 保存失败不暂停当前战斗，但显示常驻警告，下一次成功保存后清除。浏览器清理站点数据会同时删除主备，这不是云备份。

## 恢复边界

当前保存的是征途检查点、剧情选择和奖励领取阶段，不是完整的战斗中途快照。退出未结算战斗后会重新开始该场战斗。上一检查点备份恢复可能回退最近一次选择/领取；提示不得暗示零进度损失。

## 桌面后续实现契约

为 SAVE_STORE.backend 提供同步 getItem/setItem/removeItem 边界。仅允许固定存储键，不接受任意路径。桌面主进程在用户数据目录管理文件；渲染进程不能直接获得文件系统权限。

文件实现需要：临时写入并 flush、原子替换、已有有效版本备份；显式区分无文件与读失败；故障后不覆盖唯一有效副本；跨版本迁移、中文路径、非管理员账户、强制退出和重启测试。不能把网页两键备份测试当作文件原子性证明。

发布前还需要导出/导入或支持人员可操作的恢复方式，以及明确的检查点说明。Steam Cloud 必须在可靠本地存档之后单独实现冲突策略；当前未实现。

## 当前证据

- tools/test-save-store.js：主备轮换、损坏恢复、主写失败、备份写失败、读权限拒绝、未来版本保护、清除失败/成功、旧档迁移、无效字段和干净默认值。
- tools/verify-save-notices.js：真实浏览器双语告警、文本边界、准确恢复及未来版本原文保留。
- tools/verify-story-checkpoints.js：战后对白、固定奖励候选、拿牌/拿遗物和分支续档，不重复发放。
