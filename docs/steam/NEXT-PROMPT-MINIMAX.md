# 可直接交给 MINIMAX 的下一步任务：R1 Windows 桌面试玩版

你接手 `Z:\00-游戏\portrait-card-game`。请直接实现本阶段并交付可运行产物，不只写方案。开始前读取项目内适用的 AGENTS.md，检查当前 Git 状态并保留他人的修改。若创建分支，用 `codex/` 前缀。

## 一、目标与范围

把当前网页游戏做成可独立运行、离线可玩、进度可靠保留的 Windows 桌面试玩版，为真人测试与后续 Steam 发行建立基础。

本阶段只做 R1；完成后提供实物、报告和遗留问题供设计侧验收，不自行推进 R2–R5。本阶段不等于 Steam 发行成功，也不要求拥有 Steam AppID 才能完成本地桌面工作。

先读：

1. `README.md`
2. `docs/steam/PRODUCT-PLAN.md`
3. `docs/optimization/RELEASE-AUDIT.md`、`REVIEW-RESPONSE.md`
4. `src/core/save-store.js`、`run.js`、`progress.js`
5. `src/game.js`、`index.html`、`tools/package.ps1`

核查时的基线是 `91117eb` / `20261018-review-polish`；如果工作树已前进，记录新的版本与差异，不回退到旧提交。既有记录为 9238/0，必须重新运行相关检查，不能复制旧结果。

保持默认玩法、卡牌数值、敌人招式、难度/奖励经济、剧情与两境域素材。六张特色初始牌及狼群招式仍按原实验开关启用，不顺手转成默认。保留网页预览及现有浏览器数据，不重写 Phaser、不开始横屏全面改版、不批量生成新图。本次任务不包含 GitHub Pages 部署、Steam 购买/提交/公开发售。

## 二、桌面运行与构建

1. 优先验证 Electron 容器，使用执行当时受支持的稳定版本并锁定依赖。若有明确的兼容性或包体证据需要其他方案，写明理由后选用，不做无界框架重构。
2. 先验证本地页面、Phaser、字体、WebP、OGG/AAC 回退、大字阅读 dialog、存储桥接；验证成功后扩到全部场景。
3. 玩家端运行不需要 Node/Python、开发服务器或 GitHub Pages。资源来自安装包；推荐受控的本地协议，不能假定原页面直接 file:// 可用，也不能用关闭 webSecurity 解决加载问题。
4. 若用 Electron，保持渲染隔离与沙箱，页面不获得通用 Node/文件系统/命令执行接口。主进程只暴露经过校验的必要存储及窗口操作，限制非预期导航与新窗口。参考执行时的官方文档。
5. 交付 Windows x64 可解压运行包和安装包；从另一目录执行，不能依赖当前 cwd。安装目录不放玩家存档；普通用户运行不要求管理员权限。尚未签名如实标注，不把签名当已完成。
6. 构建脚本生成版本、运行资源清单和 SHA-256；使用锁文件可从干净源副本重建。运行包包含实际引用资源与许可，不把 `.git`、开发依赖、临时生成图、测试资料和个人文件打进去。原网页交接 ZIP 与桌面发行包用途不同，不能直接把整个开发 ZIP 套进容器。
7. 保留源素材；只优化桌面包的收录清单，不删除项目文件。增加窗口/全屏、合理最小窗口、Alt-Tab、关闭退出和窗口位置恢复。恢复到已拔掉的显示器时仍应可见。

## 三、完整的存储适配

先形成存储键清单。当前已观察到：

| 类别 | 当前键或入口 |
|---|---|
| 本局与备份 | `darkforest.run`、`darkforest.run.backup`，SAVE_STORE |
| 收藏/本地成就 | `black-forest-progress-v1`，progress.js |
| 语言 | `black-forest-language`，i18n.js |
| 音效 | `black-forest-audio-settings`，audio.js |
| 音乐 | `black-forest-music-settings`，music.js |
| 减少动态/触感 | `black-forest-ui-settings`，ui-skin.js |
| 阅读字号 | `black-forest-reading-size`，hand-reader.js |

重新扫描补齐漏项。只给 SAVE_STORE 接一个后端不算完成。网页后端继续保留原键；桌面后端统一落到用户数据目录，并解释正式资料、测试资料及版本之间的边界。

要求：

- 临时文件写入、可靠替换、保留最近有效备份；成功提示必须对应实际持久化。当前接口同步，若改为异步需正确传播完成/失败结果和启动恢复顺序，不能把 Promise 当布尔成功。
- 检查点内容、待领卡牌/遗物、事件选择、商店购买/删牌状态、难度、剧情分支保持一致。明确战斗中关闭后恢复到哪个检查点；不要冒充支持任意时刻续战。
- 损坏主档能恢复有效备份；备份也坏时保留原文件并提示。未知的新版本格式不得自动覆盖；写入失败不能让下一次启动读取半份数据。
- 处理创建新局、清除本局和结局清档被中断的情形，不能把已完成或已放弃的旧局通过备份复活。重开本局不清除收藏及偏好。
- 非管理员账户、中文/空格路径、只读/拒写、磁盘写失败和重复打开程序应有明确行为。可以用故障注入验证错误路径，报告需区分模拟故障与真实系统测试。
- 提供玩家主动操作的网页导出与桌面导入，覆盖本局/收藏/设置；校验版本、字段、ID、值域及大小。导入前备份桌面现有资料并明确是否覆盖，失败不破坏两端数据。不要扫描或读取其他浏览器的用户目录。
- 更新“保存在当前浏览器”等提示为对应平台的准确中英文说明；语言 ID 与玩法 ID 不改变。
