# 存储契约 · 黑森林 Windows 桌面试玩版

日期：2026-10-19。对应阶段：R1（桌面试玩版）。适用版本：`20261018-review-polish` + 桌面容器 `1.0.0`。

本文件描述桌面版把数据放在哪里、什么时候写、坏了怎么办、怎么从网页版迁移。
网页版仍用浏览器 `localStorage`，键名与值格式与桌面版完全一致。

---

## 1. 数据类别与键名

键名清单是 2026-10-19 对 `src/` 与 `locales/` 全量扫描的结果，并由
`tools/test-storage-backend.js` 持续盯住：清单里的键必须被代码用到，
代码里用到的键必须在清单里，且**除 `src/core/storage-backend.js` 外任何文件都不得直接访问
`localStorage`**。以后再加一个绕过存储入口的键，这套测试会直接失败。

| 类别 | 键名 | 内容 | 写入时机 | 网页版位置 |
|---|---|---|---|---|
| 本局检查点 | `darkforest.run` | 当前局的完整检查点（牌组、遗物、金币、章节、难度、剧情分支、商店状态） | 战斗开始/出牌/结束回合、奖励领取、事件选择、商店购买、剧情选择之后 | `localStorage` |
| 上一检查点 | `darkforest.run.backup` | 上一次写入前的 `darkforest.run` 原值 | 每次写 `darkforest.run` 之前先轮转 | `localStorage` |
| 收藏与成就 | `black-forest-progress-v1` | 已收集卡牌/遗物、已击败敌人、已触发事件、已通关记录 | 击杀、事件结算、章节结束 | `localStorage` |
| 语言 | `black-forest-language` | `zh-CN` / `en` | 标题页切换语言时 | `localStorage` |
| 音效 | `black-forest-audio-settings` | `{volume, muted}` | 菜单里改音量/静音时 | `localStorage` |
| 音乐 | `black-forest-music-settings` | `{volume, muted}` | 菜单里改音量/静音时 | `localStorage` |
| 减少动态/触感 | `black-forest-ui-settings` | `{reducedMotion, haptics}` | 菜单里切换时 | `localStorage` |
| 阅读字号 | `black-forest-reading-size` | `16`–`28` 的整数 | 手牌一览里拖动字号滑块时 | `localStorage` |

语言 ID、卡牌 ID、传承 ID、难度 ID 在两端都不变。换语言不重置本局；重开本局不清收藏与偏好。

## 2. 桌面版的文件位置

```
%APPDATA%\Black Forest\data\<profile>\
├─ data\                     ← 八个键各一个文件
│   ├─ darkforest.run.json
│   ├─ darkforest.run.json.bak
│   ├─ darkforest.run.backup.json
│   ├─ black-forest-progress-v1.json
│   └─ ...
├─ exports\                  ← 导出的进度文件
├─ backups\import-<时间戳>\  ← 每次导入前自动做的整目录备份
├─ logs\runtime.log          ← 启动、资源失败、被拦截的外网请求
└─ window-state.json         ← 窗口位置/尺寸/全屏状态
```

- **安装目录里不放任何玩家数据。** 重装、换版本、移动安装位置都不影响进度。
- `<profile>` 默认 `default`（正式资料）。自动化验收一律用 `--profile=test`，
  目录是 `data\test\`，与正式资料完全分开，测试不会污染玩家进度。
- `--data-dir=<路径>` 可以把整个资料根挪到别处。中文路径、带空格的路径都用它验证过
  （见 R1 报告 D08）。
- 窗口状态存在资料目录而不是安装目录，重装不丢；装到新位置也不会把别人的存档搅乱。

### 磁盘格式

每个键一个文件，信封结构：

```json
{ "format": 1, "key": "darkforest.run", "value": "<游戏侧原始字符串>", "updatedAt": "2026-10-19T12:00:00.000Z" }
```

`value` 里装的是**和网页版 `localStorage` 完全一样的原始字符串**，所以两边可以互相导入，
不需要任何转换层。`format` 是磁盘信封版本，和游戏内存档的 `schemaVersion` 是两回事。

## 3. 写入语义

| 情形 | 行为 |
|---|---|
| 正常写入 | 先写 `<键>.json.tmp` → `fsync` → 把旧的完好主档轮转到 `<键>.json.bak` → 原子改名覆盖主档 |
| 写入中断（崩溃/断电） | 主档始终是一份完整数据。残留的 `.tmp` 不会被当成内容读出来 |
| 磁盘写失败（拒写/空间满） | 报告 `writeFailure`，**旧数据原封不动**，界面弹出「本次进度未能保存」 |
| 写入失败却提示成功 | 不可能。成功提示对应真实的 `fsync` + 改名完成 |
| 删除键 | 主档、侧车备份、临时文件一起删，避免旧局被备份复活 |
| 清空本局 | 先删 `darkforest.run.backup` 再删 `darkforest.run`。中途被打断，旧局不会被备份复活 |

界面提示与实际持久化一一对应：`SAVE_STORE.write()` 返回 `false` 时弹出失败提示，
成功提示只在主档真正替换完成后出现。
这条保证有两处盯着：`tools/test-save-store.js` 里「后端用返回 false 失败」的用例，
以及 D06 的「只读主档」实机场景（写入返回 false、状态 `writeFailure`、旧数据未被破坏）。

## 4. 检查点语义（明确不承诺的事）

- **支持的粒度是检查点，不是战斗中任意时刻。** 战斗中关闭游戏，恢复到的是**上一个已落盘的检查点**
  （通常是出牌前或回合开始前），不是半局状态。
- 落盘检查点的时机：战斗开始、出牌、结束回合、奖励领取、事件抉择、商店购买、剧情选择。
- 「战斗中关闭后恢复到哪个检查点」由上面这些时机决定；本阶段不承诺战斗中途续战。
- 待领卡牌/遗物、事件选择、商店购买与删牌状态、难度、剧情分支都写在同一个检查点里，
  恢复后保持一致；已确认的选择不会被重复发放，也不会回滚。
- 结局清档（通关或战败后的收尾）走同一条 `clearSave()` 路径：备份先删，主档后删。

## 5. 损坏、未来格式与恢复路径

| 情形 | 检测方式 | 处理 | 玩家看到 |
|---|---|---|---|
| 主档损坏 | 信封 JSON 解析失败 | 自动回落到同键的 `.bak` 侧车；坏文件本身**不删** | 「主存档损坏或缺失，已读取上一检查点备份」 |
| 主档与备份都坏 | 两者都解析失败 | 保留原文件，不做任何写入 | 「存档和备份无法读取，原数据未删除」 |
| 游戏存档来自更新版本 | `schemaVersion` 高于本客户端 | **既不覆盖也不删除**，写入与删除都被拒绝 | 「此存档来自更新版本。请更新游戏后读取；不会自动覆盖」 |
| 磁盘信封来自更新版本 | 信封 `format` 高于本程序 | 同上 | 同上 |
| 玩家明确放弃这份存档 | 标题页弹出确认 | 玩家点头后才强制清除，解除保护 | 标题页提示条 |

「未来格式」保护是**自动**生效的：不需要玩家做任何事，旧包打开新包的档时那份档不会被偷偷改写。
玩家的出口是标题页的一次明确确认（`开始新征途 / 重新开始`），确认文案会说明这份存档会被丢弃。

## 6. 网页版 ↔ 桌面版迁移

玩家主动操作，程序不扫描、不读取任何其他浏览器的用户目录。

- **网页版导出**：标题页「进度备份 · 导出」→「导出进度文件」，浏览器下载一个 JSON 文件。
- **桌面版导入**：标题页「进度备份 · 导出」→「从文件导入进度」，选文件 → 校验 → 确认覆盖 → 写入。
- **桌面版导出**：同一入口，走系统另存为对话框，文件由玩家自己指定位置。

文件格式：

```json
{
  "format": "black-forest-transfer",
  "version": 1,
  "exportedAt": "2026-10-19T12:00:00.000Z",
  "source": "web",
  "appVersion": "20261018-review-polish",
  "data": { "darkforest.run": "<原始字符串>", "black-forest-language": "zh-CN" }
}
```

导入校验（渲染进程与主进程各做一遍，主进程用的是游戏本体同一套规则）：

1. 文件格式串必须是 `black-forest-transfer`，版本必须是 1。
2. 整体不超过 2 MB，单个键不超过 512 KB。
3. 键名必须在已知八个键里；值必须是字符串。
4. `darkforest.run` / `darkforest.run.backup` 用 `RUN._parseSave` 校验：牌组里的卡牌 ID 必须存在、
   数值字段合法、章节与难度合法；来自更新版本的存档直接拒绝。
5. `black-forest-progress-v1` 用 `META_PROGRESS.validateRaw` 校验，收藏里的 ID 必须在当前版本定义表里存在。
6. 语言只能是 `zh-CN`/`en`；音量必须落在 0–1；减少动态/触感必须是布尔；阅读字号必须落在 16–28。
7. 任何一项不合格 → **整体拒绝**，不导入任何一项。

导入动作：

- 先把现有 `data\` 整目录复制到 `backups\import-<时间戳>\`。备份失败就不导入。
- 只覆盖文件里实际存在的键；文件里没有的键保持桌面原值。
- 写入过程中任何一步失败 → 报告失败，现有数据保持可读（备份仍在，可人工回退）。
- 导入完成后需要重启游戏（或回到标题页）才能看到新数据。

## 7. 升级与回退策略

- **游戏内存档升级**：存档带 `schemaVersion`。加载时旧档按 `src/core/run.js` 的迁移分支补齐字段，
  迁移成功后立刻写回（否则下次启动还要再迁一遍）。旧档缺 `starterId` 补成 `classic`；
  旧档缺 `contracts` 显式清空，不继承上一局的妖契。
- **桌面包升级**：资料目录与安装目录分离，换版本只换安装目录，进度不动。
  新版本读到旧版本的存档按上面的迁移规则处理。
- **回退**：把旧版本装回去即可，资料目录里的文件格式没变。回退不会偷偷覆盖较新的存档——
  如果旧版本读不了新格式的存档，它会报告「此存档来自更新版本」并拒绝写入。

## 8. 未来云存档的边界

本阶段**没有**云存档，也没有接入任何账号或在线服务。以下是留给后续阶段的约束，不是已实现的功能：

- 云同步必须复用上面这套键名与值格式，不能另起一套。
- 冲突判定以检查点时间与内容为准：同键不同值时，以「更晚写入且能通过当前版本校验」的一份为准，
  另一份要保留而不是丢弃。
- 未来格式的存档在云端也按「不自动覆盖」处理。
- 本地文件存档是权威副本，云端只是副本之一；离线时游戏必须完全可用。
- 桌面版与网页版共用同一个云端账号时，键名一致，导入/导出只是本地文件，云端不改变这些键的语义。
