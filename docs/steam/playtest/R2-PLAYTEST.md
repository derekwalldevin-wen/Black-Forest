# R2 首次试玩：先自测，再招募新玩家

用户选择：先自己试玩，再组织其他人。当前没有任何真人完成记录；自动测试不填入真人样本。

## 你的首轮自测（约15–20分钟）

使用 R2 候选包，先保留自动教学。记下实际版本、电脑分辨率、Windows缩放和窗口大小。

1. 新开一局，任选一套传承，按游戏内教学完成首战。记录卡住的位置、看不懂的词和误触。
2. 点牌查看但不打出；取消一次，再有意确认出牌。观察手牌、资源和特效是否符合预期。
3. 查看一张费用不足的牌，确认能读懂原因，而且没有被消耗。
4. 打开大字手牌、菜单、牌组，再关闭；确认回到原先战斗状态。
5. 完成第一次奖励选择，说明为什么拿牌或跳过；继续到第二战，检查传承教学是否符合实际牌组。
6. 在方便的检查点关闭重开，检查进度、字号、声音和教学偏好。
7. 若出现问题，提供步骤、实际结果、预期结果及截图。不要只写“不好用”。

自测者熟悉项目，记录为 `owner-familiar`，不计入“新玩家独立完成率”。不要求你为了自测而改变平时的 Windows 设置；记录当前设置即可。

## 后续8–12人无指导试玩

目标玩家：没有参与开发，可包含卡牌新手和有经验者。观察者只处理设备故障，不教操作。玩家可使用游戏自带的教学和说明。

给玩家的任务只有：“开始一局并玩到第二次战斗结束，尽量自行操作，遇到不明白的地方可以直接说出来。”不要在任务开始前提示按键或最佳打法。

在结束或退出后提问：敌人下一步做什么？格挡何时有效？两种资源如何区分？刚才为什么拿牌/跳过？还有没有想再试的一种打法？不要提示标准答案。

记录帮助次数、误触/费用不足是否理解、首战是否独立完成、第二战到达、退出原因、阅读问题和愿不愿继续。若对录屏征得同意，可保留一段无指导首局录像；未取得同意不录。

内部参考目标：至少80%能独立完成首战并解释基本资源。样本小，用于发现问题，不用于证明市场成功。R2在真人记录到位并处理阻断问题前，不标记“首次试玩验收完成”。

记录表：`R2-OBSERVATIONS.csv`。建议用匿名编号；不收集电话、身份证或微信个人资料。

## 观察与工程验证分开

- 浏览器矩阵的 DPR/viewport 仿真不是实际 Windows 系统缩放验收。
- 直接构造九张手牌、状态或奖励只验证 UI/流程，不证明自然游戏平衡。
- 若转向微信试玩，另记手机型号、系统、微信版本、网络及基础库版本；桌面通过不能替代手机通过。
