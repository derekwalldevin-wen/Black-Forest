# 黑森林 · 全界面设计交接

目标是为游戏的每一个界面提供独立参考图、说明信息层级与交互状态，并能对应到实际代码。参考图不是直接贴进游戏的整张背景，也不是数值设计文档。所有按钮、文字、图标、卡牌须拆成独立可交互组件；数值与规则从当前代码读取。

## 统一设计原则

以 1080 × 1920 逻辑坐标设计，9:16 竖屏。左右常规安全边距 48，上下 64；窄屏按比例缩放并考虑设备安全区。背景提供场景气氛，深色半透明面板保证内容对比。金色强调当前可执行的动作。正文应在实际手机上达到 14–16 CSS 像素；以 390 CSS 像素宽换算，约为 39–44 逻辑像素。标题建议 56–72 逻辑像素，主要按钮高至少 136，其他触摸区域高至少 124，保证缩放后仍达到 44 CSS 像素。以实际显示尺寸验收，不能只看原图；文字过长时换行或滚动，不靠缩小字号塞入。未选手牌可显示紧凑摘要，选中详情必须恢复上述阅读字号。

哥特篇使用深靛蓝、赭金、象牙白与灰冷水彩森林；山海篇保留相同组件结构，替换为青铜、朱砂、玉色与古籍山水。边框纹样各自变化，信息的位置与含义保持一致。装饰不能覆盖意图、费用、生命或按钮。

生命数字居中在生命条内，格挡盾图标和数字置于生命条右侧，同一水平线；格挡为零时保留位置或收起内容，避免生命条跳动。敌方生命条在立绘脚下，玩家生命条与头像组成一行，手牌与固定操作栏下置。格挡蓝光、实际扣血红光、实际回血绿光；部分格挡可同时展示蓝色与红色，并始终用盾形、数字、飘字辅助辨认。

## 页面与流程

标题分无存档和有存档两态。有存档时主按钮是继续征途，重新开始是次级动作，随后弹出抹除进度确认。选择传承突出打法差异与真实起始牌组；确认之前可返回。帮助使用分组图解，需要完整解释行动力、意图、灵韵、共鸣与构筑；文字过长时应分页或滚动，底部按钮固定。

战斗中顶部看章节、回合、金币，中部看敌人、意图和状态，玩家生命与资源集中在手牌附近。选中牌必须上浮并展开真实描述；不可用牌显示缺少哪种资源。敌方行动时结束回合按钮切换为明确的忙碌状态，不允许重复触发。立绘和特效不得遮挡生命、手牌费用与当前操作。

战利品页去掉无关战斗 HUD，突出三张候选牌，保留跳过。继续按钮的可用状态必须由奖励流程控制；存在遗物奖励时清楚表示后续仍需选择。遗物二选一当前点击即领取，参考稿中如果出现额外确认按钮需修订或另立交互变更任务。领取完成后显示获得的内容与下一步。

事件页以插画、短叙事和两至三个选项构成，每个选项同时写行为、代价和收益。金币不足时保留选项并显示原因。结果页反馈真实变化，再提供继续。删牌页显示完整可选卡牌、重复数量、分页和当前选择目的，不可把牌组浏览误当作删牌。

焦羽、灰冢、铸坊、升契单独设计，强调其独特取舍，但不新增系统规则。铸坊目前是移除后换牌或付费加牌，不可画成真实卡牌升级。升契的已有契与未持契状态必须明确，效果从代码读取。常规事件逐项核对，不只用一张通用页代替所有故事。

战败聚焦失败结果与重新开始；通关结算显示剩余生命、击杀、牌组张数、灵韵上限和遗物数。加载页显示真实加载进度。牌组浏览、暂停设置、征途进度是建议新增的页面，必须明确标注，不得据参考图宣称已实现。

## 交付与验收

SCREENS.json 是制作清单，review.html 是查看入口。pending 表示未生成；draft-needs-review 表示已有初稿但仍需改；reference-ready 表示构图可用；需要文案修订时单独记录原因。逐图检查真实流程、按钮数量、层级、文字、卡牌规则和立绘形体。模型生成的错误文案不得进入运行时。
