# 黑森林 · 逐屏设计说明

本文件说明每一个参考界面为什么这样布置，以及实施时需要读取哪些数据。编号对应 SCREENS.json。图中文字由模型生成，最终组件须使用代码中的真实数据。参考图制作进度以清单为准。

## 标题、传承与帮助

**01 首次进入标题页**：上半屏让森林与提灯建立气氛，下半屏只放开始征途和怎么玩。没有存档时不显示继续，不新增设置、图鉴等入口。主按钮进入传承选择。

**05 已有存档标题页**：保留同一背景和标题位置，主按钮换成继续征途，下面依次放重新开始、怎么玩。存档摘要展示章与生命，属于信息展示建议，不能影响存档校验。无效存档不得保留可点击的继续入口。

**02 传承选择**：三个纵向卡片对应血契、铁壁、符咒，每项有独立徽记、打法摘要与真实起始牌组。选中态用金边与勾选，不仅用颜色区分。底部确认开始与返回固定。资源只用于介绍，不显示尚未创建的回合数值。

**06 玩法帮助**：按行动力、意图、状态、灵韵与共鸣、构筑分组。符箓示例必须使用符纸等真正的符箓牌，不能使用凝神。长内容可分为两页或滚动正文，知道了按钮固定在底部。标题字号大于正文，但装饰不占据阅读空间。

**07 重新开始确认**：背景变暗且拦截输入，中央短句解释抹除当前进度。取消在左、确定在右，确定为低饱和红色。按钮等大，避免危险动作抢占全屏。取消应恢复之前的标题态。

**31 加载**：标题、提灯、进度条组成单一视觉焦点。百分比绑定实际加载事件；背景使用能提前就绪的轻量素材，不能等待本来正在加载的大背景才能显示加载页。加载中没有无效操作按钮。

## 战斗与操作状态

**03 哥特战斗**：顶部集中章节、回合与金币，下一行遗物；敌人及意图占上半屏，敌人生命在脚下。玩家生命、盾值、手牌、行动力和结束回合组成下半屏操作区。盾图标在生命条右端同一基线，玩家与敌人规则一致。

**04 山海战斗**：沿用 03 的几何结构，改变背景、材质、边角纹样和卡面风格。灵韵与行动力分开显示，并通过图标与名称区分。立绘使用当前资产，不改变帝江的无面目、六足四翼特征。章节名来自 CHAPTERS，不使用生成图中的误字。

**21 遗物详情**：靠近遗物栏的短暂说明框，不遮住敌人意图或手牌。显示真实遗物名、图标、完整效果；铁誓指环示例是开战获得六点格挡。现有流程自动消失，不额外加入领取、装备或确认操作。

**22 选中卡牌**：选中牌上浮与放大，其余牌压低，保留所有手牌。完整费用与描述可读。再点、点击提示条、上滑均能打出；提示条放在放大卡牌内部的页脚区域，不盖玩家生命或费用；与当前游戏实现保持一致。取消选中恢复原位置。

**23 资源不足**：卡牌保持在手牌内；费用圈与短提示说明缺行动力或灵韵。分别判断两种资源，零费牌仍可用。提示不拦截整个屏幕，结束回合继续可用。不能把无效点击表现为卡牌消失。

**24 敌方行动**：结束回合变为不可用并写敌方行动，手牌也不可操作。攻击前摇、命中、回收顺序清楚；生命在结算时才更新。保留相同 HUD 位置，不在等待期间跳动。

**25 完全格挡**：蓝色盾形动态帧和盾区光效，飘字显示吸收量。生命不减少，不出现红色受伤光。盾值按实际结算减少到零，光效仍短暂可见。

**26 实际扣血**：红光只围绕头像和生命条，伤害数字同步真实扣血。部分格挡同时出现蓝盾与红光，但分别写清吸收量和扣血量。直接伤害、中毒和生命代价也遵守实际变化，不靠攻击标签猜测是否扣血。

**27 实际回血**：绿色粒子与生命条边光，只在生命真正增加时触发。满血不产生虚假的回血数字或绿光。生命与 RUN 状态同步，战后恢复沿用同一组件。

**28 战斗横幅**：开场、敌方行动、胜利共享短横幅组件，文字和色调按阶段变化。胜利样例不提前出现奖励选择，手牌关闭输入，短暂反馈后切入 Reward。横幅避开生命与费用区域。

**29 战败**：全屏遮罩与弹窗层级高于手牌，彻底拦截旧战斗输入。显示倒在哪一章、击杀数，只保留重头来过，回到传承选择以便换打法。失败不会赠送参考图中没有依据的复活币或积分。

## 战利品与结算

**08 哥特选牌**：三个候选卡牌完整展示，分别有明确可点击区域；三角排布适合竖屏。跳过始终清楚，继续在奖励未完成时禁用。凝神的当前真实规则是抽两张牌，不能沿用早期图中的抽一张。

**09 山海选牌**：沿用相同选择结构，卡框与插画切换到青铜朱砂。灵韵费用使用独立图标。示意图的类型占位须替换成完整真实规则；类型不是效果说明。

**10 遗物二选一**：两个候选等权展示图标、名字和效果，不用无作用的故事句替代规则。当前点击候选立即领取，禁用另一件并过渡到继续；不增加多余确认步骤。

**11 奖励完成**：展示本次实际取得的内容和完成标记，继续成为唯一主要操作。没有遗物奖励时不要伪造遗物领取行。下一步可能是事件、升契或战斗，应依据路由显示，不能永远写下一场战斗。

**30 通关**：森林与古籍的收束画面，五项真实统计排成左右对齐的列表。再走一次回传承选择，返回回标题。使用当前已有生命、击杀、牌组、灵韵上限与遗物数，不引入未采集的时间、评分或星级。

## 事件通用状态与特殊节点

**12 月泉**：顶部持续展示生命与金币，插画突出不存在的月亮映在水面。三种选择把治疗、最大生命代价换遗物、离开并列呈现。永久上限损失与普通扣血必须明确区分。

**13 青丘**：山海雾林、狐尾痕迹与白毛提供叙事；界面沿用事件结构。灵韵上限增加、生命代价、治疗与删牌连同各个选项一起显示。选择后进入真实子流程，不让插画暗示额外战斗。

**14 事件结果**：旧选项全部撤去，结果短文下列出真实变化与获得物。继续在固定位置；事件致死时提示结果并进入已有战败流程，不能以绿色成功样式掩盖死亡。效果日志溢出需滚动或增加面板高度。

**15 删牌**：相同卡牌按种类合并，用数量角标表示拥有份数。现有每页十二种，四列最多三行，不满的最后一行居中。直接点击移除一份并显示结果；翻页按钮在第一页和最后一页禁用。没有售卖、升级或多选操作。

**16 金币不足**：按钮仍保留代价、收益和不足原因；文字保持可读，不仅变暗。没有费用的离开选项保持可用。显示当前金币与所需金币，不能先扣金币再发现不可执行。

**17 焦羽**：一根余烬羽毛与清楚的三个选择：获得祸斗契、治疗、离开。获得妖契是这次事件的核心，火焰图标用于说明，不把契画成卡牌入手。

**18 灰冢**：无名墓与未灭火种，遗物选择和妖契选择并列。已持契时明确解释替代治疗，避免让玩家误以为可以重复取得同一契。图标题必须是灰冢，不能使用模型错字灰家。

**19 铸坊**：炉、砧与两条实际路径。熔铸是随机移除一张再随机换一张；淬火实际指定 rare，即稀有牌，旧选项描述的罕见需要校正。不可画成卡牌等级升级。顶部生命与金币栏须与其他事件一致。

**20 升契**：树根转为青铜台阶，体现境域转换。三个真实选择分别是升阶并随机加牌、治疗加遗物、直接离开。旧描述写三选一，但当前 card 算子直接随机加牌，不存在该选牌子流程。没有可升阶妖契时显示说明，随机加牌仍可执行，不能仅因无契禁用整个选项。

## 常规事件逐项

**篝火**：暖火与湿森林形成对比。休息是治疗；冥想进入删牌；添柴是遗物与六点伤害，不能当免费领取。

**骨堆**：骨缝中的金币与整齐骨架表达交换。搜刮、献祭、翻找的收益分别不同；两张随机卡牌必须写清数量，移除与随机移除不得混淆。

**提灯人**：暗灯和不露面的路人保留悬疑。交出火折同时写十二点生命代价和遗物；问路是固定二十点治疗，不能写成百分比。

**黑市**：小摊交易，明确六十金币买遗物与七十金币删牌。图中金币充足态与 16 的不足态使用同一组件，不能变成两套购买规则。

**古碑**：发热碑文、苔藓与旧石。献牌是随机移除，抄碑是随机加牌；不添加输入名字或猜谜操作。碑文绘画只作纹理，中文规则由 UI 绘制。

**荆棘井**：红水与荆棘提示风险。喝水显示固定二十五点治疗和下一战虚弱二；两个选项无需强行填成三项。

**狼的凝视**：眼睛在树林中，画面不是即时遭遇战。躲避的治疗与下一战易伤二必须同时可读；大声吼的十五点代价与六十金币同列。

**苔藓神龛**：没有神像，跳动石头是场景焦点。最大生命增加与治疗使用不同标签；最大生命加六与遗物是同一次选择的两个收益。

**九首**：九首形象来自现有相柳资产；不增加怪物血条。三个选项呈现灵韵上限加二与遗物、下一战中毒三、两张随机牌。长叙事分行，标题与选项优先保持可读。

**青铜阶**：向下的台阶与根系贯穿上半屏。灵韵上限增加分别为一、二；删牌是第二选项的代价。第三选项只拿四十五金币，不表示改变路线。

**浑敦之舞**：使用现有无脸六足四翼立绘，身体完整露出。舞蹈是叙事，不添加节奏小游戏。选项保留十八点伤害加两张牌、灵韵上限加二、百分之十五治疗。

**白泽之言**：白泽坐在路边，表情安静，不新增 NPC 对话树。问未来、问生存和离开分别显示完整真实收益，最大生命加十二不能简写为治疗十二。

## 建议新增的三个页面

**32 牌组浏览**：只读查看，不与删牌共享危险动作。按种类汇总数量，筛选卡牌类型，选中后展示真实费用和效果，底部返回战斗。当前牌堆图标还没有浏览功能，实施时需新增入口、关闭逻辑与输入遮罩。

**33 暂停与设置**：先做动画与震动设置及继续，不引入未实现的音频系统。暂停须冻结场景计时与动画并阻止出牌。当前存档不包含完整战斗快照，返回标题须说明当前战斗需重打；不能承诺恢复刚才的手牌和敌人血量。

**34 征途进度**：六章十八战固定线性流程的只读进度页。用已完成、当前、未到达三态表示位置，不画分支，不允许选节点传送。境域转换是现有的第三章后转入山海篇。未来若做路线选择，需单独改变运行数据与流程。
