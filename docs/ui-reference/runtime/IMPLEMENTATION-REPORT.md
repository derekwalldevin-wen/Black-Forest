同日后续美术检查新增 32 个遗物、妖契与战斗语义图标，修正战斗状态/妖契位置及事件画窗侵入遗物栏；本目录截图已更新。来源和本轮验证见 [补充美术报告](../../art-polish/REPORT.md)。

随后按用户体验反馈引入人类主角“提灯旅人”，将三个战斗导航收进菜单，重做资源刻度牌与完整行囊。旧参考作为历史保留，实际截图采用最新实现；详见 [主角与 UI 设计报告](../../hero-ui/DESIGN-REPORT.md)。

## 素材与组件

两境域分别生成金属按钮、危险按钮、羊皮纸与深色面板；透明头像、蓝盾、奖励宝箱、通关古籍和加载提灯用于各自实际界面。新增 24 个运行素材保存在 assets/ui。五张生成原图保留为 source-v1，加载背景由既有生产背景缩小得到。全部生成使用内置 image_gen。

完整提示词：GOTHIC-SKIN-PROMPT.json、SHANHAI-SKIN-PROMPT.json、HERO-PROMPTS.json、LOADING-LANTERN-PROMPT.json；切割来源、坐标和透明通道见 SKIN-ASSETS.json。切割脚本 tools/prepare-ui-skin.js、tools/prepare-loading-art.js。长面板由纹理填充和透明边框组成，避免把横向画稿拉成长条；代码独立绘制文字、数值和输入区域。加载提灯与小背景内嵌在 loading-art.js，能在大资源尚未加载时出现，进度仍绑定实际加载事件。

“玄玑”和“灰冢”正式参考图使用用户授权的 SimSun 真字体校正。三张图修字框外变化为 0，证据在上级 NATIVE-FONT-CORRECTIONS.json。游戏内直接读取中文卡名和事件名。

## 可体验的内容

- 标题、存档继续、传承选择、帮助和危险确认采用共用材质，确认与取消是真正的操作。
- 战斗保留敌人动态帧与蓝盾、红伤、绿治疗反馈；敌人名位于立绘上方，生命条位于脚下，盾值位于生命条侧边。遗物提示靠顶部，避开敌人意图。
- 选中牌在生命条与操作栏之间放大，完整规则为 40 逻辑像素。奖励三选一也改为 400×520，大号完整规则与安全画窗。费用不足显示具体资源及需求，拒绝操作保留手牌。
- 奖励候选、遗物二选一、实际领取总结、事件抉择、结果、删牌翻页、战败与通关接入真实结算流程。
- 战斗顶部牌组/征途/暂停入口可操作。牌组支持五类筛选、重复数量、分页、完整详情；浏览不改牌组。暂停冻结底层战斗时钟；减少动态与触感设置持久化。征途按真实章节敌人显示已完成/当前/未到达节点。返回标题保留征途存档，明确说明当前战斗从开头重打。

## 顺带修复

选中牌放大后，新抽牌曾可能继承放大尺寸，现使用 restW/restH。已领取的卡牌淡出时关闭输入，避免遮挡随后出现的遗物候选。重新开始确认后直接进入新传承选择，避免闭包里的旧存档判断恢复旧局。场景复用时清理旧弹窗引用。打包脚本加入 assets/ui 运行贴图。
